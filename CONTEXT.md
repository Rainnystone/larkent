# CONTEXT

Domain vocabulary for this repo. Use these words in code, tests, docs, and PR bodies. If a concept needs a new word, add it here in the same PR.

## What this is

Larkent connects CLI coding agents to Feishu/Lark bots. It is inspired by [lark-coding-agent-bridge](https://github.com/zarazhangrui/lark-coding-agent-bridge) and has been refactored around a shared multi-CLI runtime. A host can run a **profile** in the foreground (`run`), as a per-profile service (`start`), or under a supervisor console (`run --web-ui` / `start --web-ui`). The console starts the active profile and can host other profiles on demand. Each profile is one Feishu bot backed by one **agent**.

Deployment hosts are separate from agent kinds. Claude Code, Codex CLI, Kimi Code, Grok Build, Cursor CLI and Antigravity CLI are equal agents; the project is not tied to one deployment product.

## Agents

- **agent kind** (`AgentKind`): `claude`, `codex`, `kimi`, `grok`, `cursor`, `antigravity`. Derived from the descriptor tuple in `src/agent/registry.ts`, the single production registration source. Tests may independently list the registered kinds to detect drift.
- **AgentDescriptor**: the record that fully describes one agent kind. Adapter-owned metadata, factory, binary detection, options, capabilities and history access. Shared creation, capability, detection and UI entry points consume the registered descriptors.
- **AgentRegistry**: the registered descriptor tuple, derived ordered kinds and lookup (`AGENT_REGISTRY`). Detection order is derived from each descriptor's explicit priority. Adding an agent means one new adapter directory and one registry entry.
- **adapter** (`src/agent/<kind>/`): argv building, JSONL translation, model list, capability declaration, per-agent options schema. Knows nothing about Feishu.
- **JSONL process runner** (`runJsonlCli`, `src/agent/runner/`): shared implementation for agent run subprocesses, stdout/stderr, exit, stop and cleanup. Optional signal/timeouts belong to this runner API; production business idle remains in the bot. Binary probes and history queries have their own adapter-owned calls.
- **translator**: a **per-run** object with `translate(line)`, `finish()`, and `fail(error)`. It may hold session, pending text, and tool-call state. It is not a shared pure function on the descriptor. Each adapter run constructs a fresh translator and passes it to the runner.
- **envelope**: an Antigravity `<SYSTEM_MESSAGE>…</SYSTEM_MESSAGE>` block that must not become Feishu `final_text`. The translator runs a classifier in `src/agent/antigravity/envelopes.ts` immediately before emitting `final_text` from `result.response` or held-back `pendingText`. Citations stay. A balanced pair is stripped. An unclosed opener is stripped through end only when it matches an **envelope fingerprint** (a `[Message]` field within ~64 characters after the tag, or an immediately preceding **preamble** line `The following is a <SYSTEM_MESSAGE> not actually sent by the user…`). This is not the session-catalog **policy fingerprint**.

## Runs and sessions

- **run**: one invocation of an agent for one Feishu message.
- **idle bound** (`runIdleTimeoutMinutes`): default **15** minutes of stream silence ends the run as `idle_timeout` so the queue can drain. `0` or `/timeout 0` disables the watchdog. An open tool call pauses that bound for at most **60** minutes. Run handles expose `lastEventAt` (register time, then each stream event). After recovery, `runs.review(outage)` gives a silent run a **2-minute** stall deadline, then stops it with the idle-watchdog reason through the normal outcome + notice path. A silent run with an open tool call gets that deadline only when `outage.hostSuspended`; otherwise the 60-minute tool-call cap still bounds it.
- **run options** (`AgentRunOptions`): run id, prompt, cwd, optional resume handle, model, images and adapter options. The executor maps the run's effective access into validated options; the profile adapter receives its bot identity through `setBotIdentity`.
- **resume handle**: the opaque string that continues an **agent** conversation. Codex's thread id and everyone else's session id are both resume handles. Shared agent code has no other name for that handle.
- **reply mode**: `stream-deltas` or `final-answer`. Declared on the descriptor; decides how the stream maps onto Feishu card updates.
- **session catalog** (`sessions.json.catalog.json`, that is `${sessionsFile}.catalog.json`): per profile, maps Feishu scopes to resume handles plus the policy fingerprint they were created under.
- **policy fingerprint**: SHA-256 over the inputs that decide whether a stored session may resume. V2 stability is a pinned contract.

## Profiles and runtime

- **profile**: one bot's on-disk configuration. Feishu app identity plus an `agent` block: `kind`, optional `binaryPath`, `options`.
- **runtime ownership**: each profile owns its adapter instance, identity, session state and active runs. Each run owns its subprocess and translator state. Shared working directories and existing CLI login environments are allowed; this is not filesystem or account isolation.
- **supervisor**: hosts profile runtimes with separate sessions, locks and process registry entries.
- **settlement**: the executor retains scope/active-run ownership until child exit and adapter cleanup succeed. A terminal event alone is not settlement. `stop()` rejects on settlement failure; profile shutdown waits for consumers and store flushes and reports failures.
- **process registry** and **runtime locks**: per-profile bookkeeping on disk so two supervisors do not fight over one profile.
- **preflight**: checks that the agent binary exists and answers. Onboarding uses `detectInstalledAgents`. The in-chat `/doctor` command is a per-profile echo, not a CLI.

## Persistence rules

- Profile documents use `schemaVersion: 3`, including `agent.kind`, optional `agent.binaryPath` and `agent.options`. The session catalog uses v2.
- SessionStore uses v2 `{ schemaVersion, entries }`; entries use `resumeHandle`, preserve cwd/timestamps and allow idle-only preferences. The loader upgrades the legacy unversioned scope map and its `sessionId`.
- WorkspaceStore uses v2 `{ schemaVersion, chats, named }`, preserving chat and named workspace mappings. Its loader upgrades legacy v1 documents.
- Loaders validate supported formats, atomically persist required upgrades and expose the current shape. Unsupported future versions are rejected without replacing the original. Store flush and shutdown propagate persistence failures.
- New-profile bootstrap resolves binary env settings into `agent.binaryPath`; stored profile paths take precedence afterward. Bridge data roots do not replace `HOME` or CLI login state.
- A code rollback does not downgrade data. Restore matching data backups before running an older version.

## Self-heal and backfill

- **self-heal**: recovery the bridge performs on its own after a disconnect, sleep, freeze or restart. No external watcher, poller or host routine is assumed. Lives in `src/bot/`, identical for every profile and agent kind.
- **link**: the bridge's belief about whether Feishu is reachable, both WebSocket and REST. Owned by **FeishuLink**, created before `channel.connect()` so no message is handled with unwrapped outbound or an always-up stub. Outbound send, card updates, and intake REST (`getChatMode`, `getAppInfo`, chat/message lookups) are wrapped here with a per-request deadline that starts at the call — including TCP connect, which the SDK `httpTimeoutMs` does not cover. The stream lifetime is not timed (I7). Runs read the live link through a getter (`outageEpoch` / `isDown`), never a captured stub. One classifier (`classify`) maps every Feishu error to `link`, `rejected`, or `local`: link errors take the link down; success and rejected 4xx are evidence; a local error is neither. Every tick runs gap detection and updates `lastTickAt`, including while a probe is in flight. A wall-clock tick gap over 30 s still takes the link down and discards a late probe (`probeSeq`), but `Outage.hostSuspended` is true only with real OS sleep evidence inside the gap (Linux `/proc/uptime` BOOTTIME minus monotonic; macOS `kern.waketime`/`kern.sleeptime`; Windows Kernel-Power sleep/wake in the System log). A process freeze (`SIGSTOP`) is not sleep. Probe failure, timeout, or missing APIs mean not suspended and must not block recovery. A detected gap bumps `probeSeq` so a late probe result is discarded. The authenticated probe keeps `raceProbe` at `FEISHU_LINK_PROBE_TIMEOUT_MS` (below the sleep threshold): timeout aborts/ignores `getAppInfo` so a late success cannot take the link up. Probe REST is bound before outbound wrap so wrap `onResult` cannot `goUp` a timed-out probe.
- **outage**: an interval `{since, until, hostSuspended}`; `since` is the last positive evidence of reachability, `until` the first fresh evidence after it. `hostSuspended` is true only with real OS sleep evidence inside that interval. A wall-clock jump, process freeze, or link evidence alone (WebSocket down, probe failed or timed out, outbound link error) leaves it false.
- **recovery signal**: FeishuLink emits `recovered({since, until, hostSuspended})` exactly once per outage. Process start and supervisor swap call `recover()`, which is the same Recovery path. Nothing else triggers **backfill** — in particular, not connected ticks, not SDK `reconnected` by itself, and not SDK keepalive or an unrecoverable WebSocket. A live bounded outbox sweep may resend staged 4xx/local replies without a recovery signal; it does not scan history.
- **transport-only reconnect**: SDK keepalive owns WebSocket reconnect (`keepalive.enabled`). The bridge never calls `controls.restart` for a stuck or failed link; `onUnrecoverable` only logs. There is no `keepalive-restart` stop reason and no 保活重启 notice. `/reconnect` and `/account` remain the only callers of `controls.restart`.
- **outbox**: the turn journal's narrow delivery interface (`stageReply`, `replyDelivered`, `stageNotice`, `noticeDelivered`, `redeliver`, `reapOrphans`). Reply and notice are separate staged items with per-item state and receipts (`reply.state` / `notice.state`: staged, sent, rejected, voided), independent of run `status`. Abandoning a continuation voids only the notice; supersede and `/new` still void a staged reply. Every terminal reply is staged before its first attempt in every reply mode, including streamed card and markdown. Each final reply and notice carries a stable `deliveryId` as the Feishu `uuid`. Trust only the returned `message_id`, never an echoed body. Delivery of a streamed answer is the awaited `stream()` result, never a throttled `update`/`setContent`. A failed final stream stays staged when a card receipt is known; redelivery patches that same interactive card. One classifier (`classify`) sorts every Feishu error into `link`, `rejected`, or `local`. While the link is down, delivery stages and returns (I6); Recovery delivers and stops at the first link error. While the link stays up, a bounded outbox sweep retries staged rejected/local replies. A gone card falls back to one uuid-keyed send using the stored `deliveryId`. Other rejected patches stay staged. Outside the 1-hour uuid window, reply redelivery lists the chat first and matches `parent_id` + bot app id + `create_time`. There is no in-process delivery lock or live-notice send set.
- **backfill**: the idempotent catch-up routine that Recovery runs after redelivering the outbox: pull recent history with **bot identity** for listed groups and **session-known p2p** chats, keep survivors that are not in the processed ledger, and hand them to the normal `intakeMessage` path. Group @-mention filtering matches live intake (`requireMentionForChat`): a mention-free group is recovered without an @. p2p keeps ordinary human messages (no @ required). `maxMentionsPerChat` is the newest-first enqueue cap per chat for both (group @mentions and p2p human messages); truncated ids are not recorded as processed. The preference key is not renamed. Not a poller; it never runs on a timer.
- **session-known p2p**: a DM chat id already present as a session / catalog scope that `getChatMode` resolves as `'p2p'`. Backfill unions those ids with `listChats` groups. Unique session chat ids are classified concurrently, unlisted first, and bounded by `maxChats`. `maxChats` applies to that combined list and preserves discovered p2p ids within the cap. A first-contact DM with no prior session entry is out of scope.
- **live watermark** (`lastLiveAt`): the last positive evidence of Feishu reachability (probe ok, inbound event, or later outbound ok), persisted per profile. Written only by FeishuLink. Connected ticks without evidence do not advance it.
- **backfill window**: `[max(now − lookbackMs, min(since, incompleteFrom) − margin), now]`. There is no `minGapMs` skip and `lastBackfillEnd` is not part of the window.
- **processed ledger** (`backfill-state.json`, schema v1): per-profile store of processed `message_id`s plus the watermarks. Owned by the supervisor per profile and injected into `startChannel` like `sessions`, so it survives `controls.restart()`. The loader stays on v1 and ignores unknown fields. `unrecord` removes an id (and its in-flight claim) so a later recovery can accept it again.
- **incomplete scan**: a backfill kept open by a transient per-chat failure (HTTP 5xx, HTTP 408, HTTP 429, network, timeout, or no determinable HTTP status), a global chat-list failure, or a session mode lookup that failed the same way. A non-retryable per-chat HTTP 4xx skips that chat for the window and does not by itself keep the scan incomplete. `lastBackfillEnd` is leftover: old files still load it, the next save drops it, and it is not part of the window. The ledger keeps `incompleteFrom` so the next recovery retries that window even if FeishuLink has already moved `lastLiveAt`. Truncation of `maxMentionsPerChat` also leaves `incompleteFrom` so the dropped ids stay recoverable. An outage longer than `lookbackMs` logs `backfill.window-truncated` once per recovery (log-only; no per-chat notice).
- **reliability** (`profile.reliability`): leftover key. Loaders strip `notice` and the six match-master flags; the object is omitted on save. Interruption notices are always on and signed. Lost-message recovery, run outcome, CLI signatures, journal writes, and journal recovery are always on. Short-gap skip is gone: every recovery scans.
- **continuation**: the per-scope offer to resume an interrupted turn, owned by `Continuations` (`src/bot/continuation.ts`). `take` runs once per batch. An ordinary follow-up **abandons** the interrupted turn (card 已放弃, abandon instruction, no continue hint, only the new message is answered). The 继续 button or typed 继续 **continues** exactly once (card 已继续, resume handle plus continue hint). A later click replies 此继续已失效. `/new`, `/cd`, `/ws`, and `/resume` void the offer. State is `continuation.status` on the turn journal and survives restart. The consecutive-interrupt streak lives in this module.
- **interruption notice**: a new message after a run ends `interrupted` (not user-stop or session switch) or retriable `failed`/`partial`. @ the initiator, offer 继续 (`notice.continue`) / 暂不 (`notice.dismiss`), and say “或 @bot 继续” when the chat requires a mention. Auth-required tells the initiator once in chat and DMs the owner once, with no continue button. Continue uses the same resume handle plus a one-time **continue hint** and does not replay the original prompt; without a handle it reruns the original batch from stored **userInput**. Any allowed user in that chat may click continue. Button actions bind turnId + the journal entry's **policy fingerprint** + a one-time nonce + TTL and die after session switch (`noticeInvalidated`) or fingerprint change. **consecutiveInterrupts** is the per-scope streak persisted on the journal entry: three notices keep buttons; the fourth is **plain** text; an ordinary user message or session switch (`/new`, `/cd`) resets the count. Failed sends stay journal-pending (`notice-pending`) and are rate-limited after restart.
- **turn journal** (`turn-journal.json`, schema v1): per-profile file for one user turn from enqueue to reply delivery (and later notice delivery). Supervisor-owned and injected into `startChannel` like the ledger, so it survives `controls.restart()`. Run states include `queued`, `running`, `settled`, `interrupted`, and `voided`; delivery still projects `reply-delivered`, `completed-undelivered`, `notice-pending`, and `notice-delivered` from per-item `reply.state` / `notice.state`. Old files that only have the shared `status` load and redeliver staged items once. `/new` and `supersedeSession` void incomplete records for that scope; later settle/reply updates cannot un-void them. A code rollback ignores the file. Startup recovery reaps a still-living child matched by pid + start time, then marks the turn interrupted. Recovery redelivers staged replies and notices under the persisted `deliveryId`; a streamed card whose final write failed is patched in place rather than posted as a new message.
- **stop reason** (`stopRequest`): why the bridge asked a run to stop. Set at the call site, first writer wins. Distinct from the runner-internal finish reason (how the CLI stopped).
- **run outcome** (`RunOutcome`): the unique end classification derived from stop reason, exit/signal, terminal event, stderr tail, per-adapter CLI signatures, and `outageOverlapped` (the link's outage epoch changed during the run, or the run started while the link was already down). `unclassified` is retriable; if it overlapped an outage its cause is `transient-upstream`. CLI signatures choose card wording and `needsHuman` (auth, quota). Card terminal, notice decisions and `card.final` / `run.failed` logs all come from this value. Cards show the signature's redacted copy; raw stderr stays in local logs.
- **stderr snapshot**: the bounded head+tail copy of CLI stderr on `AgentRun` (`stderrSnapshot`). Same idea as the spec's stderr tail; matching uses this buffer, not a 500-character error slice.
- **synthetic** (CLI signature): a table entry verified only with invented goldens, not seen in real bridge logs (grok/kimi in ticket 5).
- **recover()**: the single Recovery entry. Order is reap orphans, redeliver staged replies/notices, backfill the outage window, then review active runs. Each step has its own try/catch (I9): one failure does not skip the others, and a failed window is re-queued for the next recovery. Coalesced: one in flight plus one queued. Run review gives a silent run a 2-minute stall deadline; a silent run with an open tool call gets that deadline only when `outage.hostSuspended`. Process start (FeishuLink starts down) and supervisor swap both call it. `recoverMissed` is an alias. An optional `outage` argument supplies `{since, until, hostSuspended}`; omitted, it uses the live watermark through now with `hostSuspended: false`. Automatic `onRecovered` runs are caught by `trackConsumer` (`recovery`); a failed step is logged and the bridge stays up. After redeliver, a live sweep retries any remaining staged rejected/local replies while the link stays up.
- **claim**: the synchronous check-and-reserve of a `message_id` at `intakeMessage` entry. Released if the message is gated out, or if intake fails or times out before the turn is accepted into the queue or journal — so a later backfill can answer it exactly once. A link-class failure also marks the scan incomplete. Recorded as processed once it is accepted (queued or handled as a command). Unrecorded if that accepted work is abandoned before it starts — disconnect, `reconnect-in-progress` reject, a flush that fires after `closing`, or a later recovery handoff — so the same id can be claimed again. A semantic-cancel command (`/stop`, `/new`, `/cd`, `/ws use`, `/resume use`, `/exit`) keeps the record and confirms the drop instead of unrecording it.
- **backfill mark**: bridge-side note that a queued message came from backfill; `runAgentBatch` turns it into one lateness hint in the prompt. `NormalizedMessage` is not extended.
- **lateness hint**: the single `extraInstructions` line that tells the agent the triggering messages were posted while the bot was offline. A backfilled run differs from the identical live run by this line only.
- **kill switch**: `preferences.backfill.enabled: false`. No scan; the live watermark still advances.
- **dry-run**: `preferences.backfill.dryRun: true`. The scan runs and logs `backfill.would-enqueue`; nothing is handed to intake.
- **coalesce**: a second recovery signal while a scan is in-flight returns the same promise and logs `backfill.coalesced`.
- **bridge-owned final reply**: one user turn has one authoritative post to the triggering chat, sent by the bridge. If the agent already IM-sent to that chat, the bridge skips (`outbound.skip-cli-already-sent`).

## Words we do not use

- "default agent". There is none.
- "poller" or "patrol" for recovery. Backfill runs on recovery signals, never on a schedule.
- Agent resume fields named `sessionId` or `threadId` outside an adapter or a migration. Shared agent code says `resumeHandle`.
- "built-in" versus "added" agents. All registered kinds are equal.

Existing CLI/card/history DTO fields may retain their specified protocol names; the current SessionStore memory and disk fields use `resumeHandle`. Feishu routing still uses protocol `thread_id` / `threadId` in `src/bot/scope.ts` and the channel SDK. QR onboarding still uses a Feishu `sessionId`. Those are not resume handles. Do not rename them.
