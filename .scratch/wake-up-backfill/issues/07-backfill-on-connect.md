# 07: Backfill on connect — answer @mentions missed while offline, once, with a lateness hint

**What to build:** The core self-heal slice. When a bridge finishes connecting (process start, keepalive wake-up → restart, `/reconnect`, `/account`) and the gap since the live watermark is at least `minGapMs`, it runs **backfill**: lists the groups the bot is in with bot identity, applies the access-mode pre-filter and optional `chats` override, pages each in-scope chat's history inside the **backfill window**, normalizes items with the SDK so `mentionedBot` is computed the same way as for live events, applies rules R1–R6 (deleted, self, not-mentioned, already processed, slash command, newest-N cap), and hands the survivors oldest-first to the unchanged `intakeMessage`. Each survivor carries a **backfill mark**; the resulting run's prompt gets one lateness hint line. Multiple missed @ in one scope merge into one run through the normal debounce. With `dryRun: true` the whole scan runs and logs `backfill.would-enqueue` instead of handing anything to intake — the safe first demo on a real profile. A missing watermark initializes and does not scan. Per-chat API failures are isolated; the watermark and `lastBackfillEnd` advance when the scan completes.
