## Rule for "what counts as an answer" (and why)

When `AntigravityJsonlTranslator.translateResult` (`src/agent/antigravity/jsonl.ts`) receives a `result` with `status: 'ERROR' | 'FAILED'`, it finishes the turn as a delivered reply (`final_text` + `{ type: 'done', terminationReason: 'normal', invalidateResume }`) if and only if **all five** conditions hold:

1. **`finished_reason` is neither `'interrupted'` nor `'print_timeout'`** (`!keepSession`).
   - *Reason*: Intentional SIGTERM stops (`interrupted`) and CLI print caps (`print_timeout`) are non-sticky and intentionally keep their existing handling and resumable session handle.
2. **`lastStepType === 'agent_response'`**.
   - *Reason*: As Ticket 01 proved (`error-interim-narration.jsonl` / `bcafc5d7`), `agy` concatenates pre-tool / interim narration into both `result.response` and held-back `FinalAnswerCore` `pending` even when later steps fail on `error_message`. Requiring the final step before `result` to be `agent_response` rejects mid-turn failures after interim narration.
3. **The trailing `agent_response` step reached `state === 'DONE'`** (`trailingAgentDone`).
   - *Reason*: Distinguishes a finished reply (all three 2026-11-13 sticky-ERROR-with-answer incidents `5d25dff0`, `939b4832`, `b4314394` and capture `288d45af` ended on `agent_response` `DONE`) from a fragment cut off mid-sentence while still `ACTIVE`.
4. **No tool step remains open** (`openTools.size === 0`).
   - *Reason*: Every `tool` `ACTIVE` step in the turn paired with `DONE`; prevents treating a partial status message emitted while a background tool was still `ACTIVE` (`print-timeout-open-tool.jsonl` shape) as a completed answer even if `finished_reason` is absent or `'error'`.
5. **Both the trailing `DONE` `agent_response` step's own text and the resolved full answer (`result.response`, falling back to `FinalAnswerCore.pendingText()`) are non-empty after `scrubSystemMessageEnvelopes(...).text.trim()`**.
   - *Reason*:
     - Checking the trailing `agent_response` step's own scrubbed text prevents a thinking-only post-tool `agent_response` (`state: 'DONE'`, empty `text_delta`, as seen on step 4 of `error-interim-narration.jsonl`) from misclassifying earlier pre-tool narration in `result.response` as a finished answer.
     - Scrubbing `<SYSTEM_MESSAGE>` and `<task_notification>` envelopes before testing non-emptiness prevents envelope-only payloads from counting as answers.
     - Resolving `result.response` when its scrubbed text is non-empty and falling back to held-back `FinalAnswerCore.pendingText()` matches `FinalAnswerCore.complete()` on `SUCCESS` and handles streams where `result.response` is omitted or blank.

## Observability and session invalidation

- **Diagnostic `warn` log**: When the rule matches, `AntigravityJsonlTranslator` logs `log.warn('agent', 'error-with-answer-recovered', { status, finished_reason, conversationId, errorMessage })` with `redactDiagnosticText` + truncation (4096 chars) and never logs reply content. `agent` `terminal-result` (`info`) still logs first on every `result`.
- **Poisoned handle still discarded (`invalidateResume` on `done`)**:
  - Because `init` / `step_update` already emitted `{ type: 'system', resumeHandle: conversationId }` earlier in the run, `SessionStore`, `SessionCatalog`, and `TurnJournal` already hold that handle by the time `result` arrives.
  - `AgentEvent`'s `done` variant now accepts optional `invalidateResume?: string`, and `invalidatedResumeHandle(event)` (`src/agent/types.ts`) is honored in `recordRunSessionEvent` (`src/bot/run-flow.ts`), `executeTurn` / `processAgentStream` (`src/bot/turn.ts`), and `handleCommentMention` (`src/bot/comments.ts`) without keying shared code off `agentId === 'antigravity'`.
  - Because the run finishes with `done` (`terminationReason: 'normal'`) -> `RunOutcome` `completed`, cards/text/comments render the normal reply without `⚠️ agent 失败`, without `下一条消息将开始新会话`, and without offering a `继续` interruption notice, while the next turn starts with no resume handle and logs `session` `fresh`.

## What Ticket 03 (`03-error-without-answer-reruns-once`) must know

1. **Ticket 02 already intercepts all sticky/recoverable `ERROR`/`FAILED` turns that finished an answer**:
   - Any Antigravity turn that reaches `event.type === 'error'` now genuinely has **no completed answer** (either `responseChars === 0`, mid-turn failure ending on `error_message` after interim narration, cut-off `ACTIVE` fragment, open tool, `interrupted`, `print_timeout`, or process/stream failure without a `result`).
2. **Distinguish `invalidateResume` errors from resumable / deterministic errors**:
   - `interrupted` and `print_timeout` emit `error` **without** `invalidateResume`; keep their existing session and `继续` card behaviour untouched.
   - Pre-attachment CLI errors (e.g. invalid `--model` flag where `agy` never attached to a conversation: `conversationId` absent, `invalidateResume` absent, `numTurns: 0`, `lastStepType: null`) also have no `invalidateResume` and fail deterministically if rerun with the same arguments.
   - Attached non-answer `ERROR`/`FAILED` turns (`error-without-response.jsonl`, `error-interim-narration.jsonl`, `9886c107`, `5d25dff0` TCP timeout) emit `{ type: 'error', terminationReason: 'failed', invalidateResume: conversationId }` and have already discarded the poisoned handle in `SessionStore`, `SessionCatalog`, and `TurnJournal` by the time the turn settles.
3. **Existing runner test seam**:
   - `tests/helpers/scripted-jsonl-cli.ts` now distinguishes `agyScript('sticky-error', ...)` (ERROR **with** answer, delivered by Ticket 02) from `agyScript('error-without-answer', ...)` (ERROR **without** answer, currently tested in `tests/integration/bot/agy-session-discard-runner.test.ts` for manual `继续` and ready to be updated by Ticket 03 for automatic single fresh rerun + no `继续` card when session was discarded).
