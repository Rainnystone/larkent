## Incident

2026-11-08 19:13:35 Asia/Shanghai. agy reported print timeout; the bridge logged exit 3 and outcome `partial`, but the card terminal stayed `error`. The user-visible text had both the print-timeout warning and an `agent 失败` tail. Log window: `~/.lark-channel/profiles/cursor/logs/bridge-20261108.jsonl:1031–1034,1052–1058`.

Cause was presentation, not classification. `deriveRunOutcome` already returns `partial` for CLI error + exit 3 + the real print-timeout stderr when there is no stop request (`signatureApplies` is true whenever `stopRequest` is unset). `reduce()` still applied the CLI error event (`terminal: 'error'`, `errorMsg`). `applyOutcomeToState` then called `finalizeIfRunning`, which no-ops when the card is already not `running`. `appendOutcomeNotice` added the signature copy; `text-renderer` printed that block **and** `⚠️ agent 失败:${errorMsg}`. `run-executor` logged `run.failed` from `terminalEvent.type === 'error'` even though `handle.outcome.kind === 'partial'`.

## What landed

- `applyOutcomeToState` maps settled `partial` to card `done` via `markDone`, which overwrites a stale CLI error terminal and clears `errorMsg`. Partial is not failed (D8).
- `appendOutcomeNotice` does not append the print-timeout copy when `finalText` or an existing text block already holds that same string. Useful partial text is kept. This is skip-if-already-present, not match-and-delete of unrelated rendered strings.
- `run-executor` logs `run.completed` with `result: 'partial'` when the settled outcome is partial. It does not emit `run.failed` / `✗ run failed` for that case.
- Antigravity `emptySuccessHint` reuses `ANTIGRAVITY_PRINT_TIMEOUT_USER_MESSAGE` (`输出不完整（打印超时），可稍后继续`).
- Continue (`planInterruptionNotice`) stays a recovery action: Chinese summary `上一轮未完成（输出不完整）`, `notice.continue`, resume of the existing handle. It does not turn partial into failed or repeat the print-timeout / `agent 失败` diagnostic.
- Genuine current-turn CLI errors without a partial signature stay `failed:unclassified` with `agent 失败`. Post-terminal SIGTERM cleanup does not change a print-timeout partial (D4).
- Ticket 03 overlay is unchanged: with a stop request, a partial signature applies only to `done`+`normal`. User-stop plus a real error terminal stays failed even when stderr matches print-timeout. The 19:13 incident had no stop request.
