## What landed

Shared `createIdleWatchdog` now:

- Tracks each grace-granting tool as `{ used, name }` from its own start.
- Caps at `max(60m, configured idle)` of awake time. Main-conversation `text`/`thinking`/`final_text` reset **normal idle only** and do not close or slide that cap (Q5).
- Retires an unpaired id at its cap (cannot reopen). Concurrent tools keep independent starts; the run stops when the last remaining grace tool hits its cap, not when an older sibling expires.
- Parent `Task` / `Agent` names do not grant 60-minute grace (Q3 name heuristic). A nested `Bash` still gets its own cap.
- Heartbeat-only `liveness` never extends idle or a tool cap (Q2).
- Document-comment tasks use this watchdog and `getRunIdleTimeoutMs` (Q4). Wall-clock `ttlMs` / `nextCommentEvent` race is gone.
- Stop request carries `timer: 'idle' | 'tool-grace'`, optional `tool`, and `awakeMinutes`. User text is `等待预算已用尽（…）` — no 卡住 / 无响应 (Q8).
- A live child `pid` or unstructured stderr never opens grace (Q6). Early `tool_use` still goes through `executeTurn` `onToolUse` / `inspectAutomationToolUse` before the consumer watchdog (Q7).
