## What landed

- Antigravity `printTimeout` is copied at adapter construction (`asAgentOptionsObject`). Editing the source object or the on-disk file does not change an existing adapter. Explicit `/reconnect` / supervisor restart builds a new adapter from disk.
- Omitted `printTimeout` still omits `--print-timeout` (agy default `0s`). Explicit `"0"` and `"0s"` are accepted and forwarded. Positive Go durations stay valid; invalid/negative/`0m`/`.1ns` stay rejected. Other agent kinds reject the option.
- `/reconnect` loads on-disk config (`assertReconnectConfig`) **before** stop/wait. Invalid options leave runs and `controls.restart` untouched and reply `重连失败`. Valid reconnect then stops or waits and restarts.
- Keepalive wake / unrecoverable WebSocket still do not call `controls.restart`, so they do not reload profile options.
- `adapter.effective-timing` logs an allowlist: reason, profile, agent kind, config path, print-timeout mode/value, idle/tool budgets. Never config dumps, argv, prompts, or credentials. Modes: `omitted` / `none` (`0`/`0s`) / `configured` / `unsupported`. Configured CLI cap also sets `cliTimeoutSleep: 'unverified'`. Idle/tool fields are the **profile defaults captured with the adapter**; the live watchdog still reads `cfg` and session `/timeout`.
- No automatic hot reload. No production config change. agy host-sleep accounting for `--print-timeout` is **unverified** (help does not specify it). A whole-turn CLI cap is not per-tool awake grace.
