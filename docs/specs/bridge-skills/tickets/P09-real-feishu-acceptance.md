# Task 9 — P09 六种 CLI 的真实飞书整体验收

**Status:** ready-for-agent · 待实施及相应真实测试授权
**Delivers:** 对同一交付版本给出六种 CLI 在真实飞书环境中的业务证据，证明完整首版范围可用，并准确列出尚未验证的环境。
**Blocked by:** [P08](P08-cutover-and-upgrade.md)
**Worker class:** judgment

## What to build

完成用户已确认的 T1–T4 验收，使用专用 profile、测试群和可控数据。P07 的真实 CLI 证据证明工具循环；本票验证飞书消息、确认、调度、身份和最终交付连接起来的实际行为。修复验收发现的范围内问题并复验，不把失败转为通过或缩小首版范围。

## Interfaces and boundaries

- 以[规格 T1–T4、A01–A16](../../bridge-skills.md)及[共同契约](README.md)为验收依据。开始前按项目真实测试指引核对允许的测试环境、部署 checkout 与版本。
- 不使用生产群做试验，不把其他环境的一次 token 代码核验当作该版本的 automation 成功证据。需人类完成的既有确认不能由模型代点。
- 本票不改平台无关 timeout、扩大业务范围或增加凭据副本；发现跨票问题在当前集成范围修复，并复验被影响的证据。

## Acceptance criteria

- [ ] 六种 CLI 分别有新会话和续会话的“消息 → 发现/读取 → 实际调用 → 本轮反馈 → 正确回复”证据，包含至少一次实际参数错误及同轮修正。
- [ ] 验证三天每天 09:00 的预览/卡片次数及结束边界；精确历史日期回归使用固定时钟，真实环境使用等价未来日期，不能为了测试创建过去任务。
- [ ] 实际人类确认后任务生效，至少完成一次可观察的自动执行；区分创建、确认、运行及交付结果。
- [ ] 验证 bot 和已授权 user 操作、创建者与执行授权的区分、授权失败与认证配置变更拒绝；记录 CLI 版本及 profile 归属，不泄露凭据。
- [ ] 验证外部纯 skill/脚本资源样本、实际脚本结果、缺依赖诊断与续会话读取；确认原生插件未受接管。
- [ ] A01–A16 每项都有对应的自动化或真实验收证据，不用 skill 读取率或模型自述代替副作用与状态检查。
- [ ] 报告固定交付提交、各 CLI/平台环境、测试数据清理结果、失败及未验证项。任何缺失的必要 CLI/权限/平台证据都保持未完成，不宣称全量验收通过。
- [ ] 交付代码的 `pnpm ci:local` 和所需平台检查通过；必要独立复核通过。验收中发生代码变更时，仅追加受影响的回归和必需门禁。

## Verification loop

1. 按已批准环境建立六 CLI × 新/续会话矩阵，关联 P01–P08 的固定版本自动化证据。
2. 逐一执行受控业务场景，核对飞书实际卡片/消息、持久化状态与执行产物；失败按原验收修复，环境不可用如实标记。
3. 完成相关复验、代码门禁及独立复核，清理本次测试资源并交付证据。只有全部必要验收成立才结束本工作流。

**Spec coverage:** T1–T4 整体证据，尤其 T4 的真实飞书部分；核对 A01–A16 无缺口。
