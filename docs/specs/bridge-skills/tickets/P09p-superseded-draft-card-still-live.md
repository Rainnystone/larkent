# Task 9p — P09p 草稿修订后旧确认卡仍有效，点「是」会重复建任务

**Status:** todo · bug · P3
**Delivers:** 未确认的 automation 草稿被修订后，旧草稿作废，旧确认卡点击被拒绝或显示已被取代，不会产生重复任务。
**Found in:** 真实飞书测试 bridge，代码 head `b4d67c6`（#52）全量回归，2026-10-20 live 复验
**Worker class:** judgment
**Blocked by:** None

## Bug

- **场景：** 测试群内创建每日 09:00 的 automation 草稿，确认前要求改为 08:30。bot 生成了第二份草稿和新确认卡，回复称两张卡都待确认、“旧卡没有被自动关掉”。
- **期望：** 同一群内修订待确认草稿后，旧草稿被取代：旧卡更新为“已被新卡取代”，点击后提示确认已失效，不创建任务。
- **实际：** 新卡确认后创建任务 #12（08:30）。2026-10-20 16:44（UTC+8）点击旧的 09:00 草稿卡「是」，仍创建了任务 #16，与 #12 重复；旧卡没有任何已取代提示。
- **严重度：** P3（可在飞书触发；用户误点旧卡即产生重复的周期任务）。

## Root cause（推测）

- `src/automations/store.ts` 约 554–561 行 `saveDraft` 只追加草稿，不会让同群 / 同 actor / 同意图的旧待确认草稿失效。
- create 路径（`src/automations/operation.ts`）没有“替换草稿”参数，模型无法声明新草稿取代旧草稿。

## What to build

- 修订待确认草稿时让旧草稿失效（显式替换选择器，或按同群同名待确认草稿判定），并更新旧卡为已取代状态。
- 点击已取代草稿的确认卡：返回“此确认已失效”，不产生副作用。

## Acceptance criteria

- [ ] 草稿修订后，旧卡被拒绝或标记为已取代。
- [ ] 新旧两张卡都点「是」，最终只有一个任务。
- [ ] 测试覆盖“修订后点击旧卡”路径。
- [ ] 在飞书测试群 live 复验。
