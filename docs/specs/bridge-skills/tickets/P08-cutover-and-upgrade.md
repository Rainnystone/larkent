# Task 8 — P08 切换新入口并保留已有任务

**Status:** ready-for-agent · 待代码实施授权
**Delivers:** 部署新版本后，模型只通过正常工具调用管理 automation；已有任务、草稿和确认卡仍能使用，历史回复标签不再产生副作用。
**Blocked by:** [P07](P07-six-cli-contract.md)
**Worker class:** judgment

## What to build

完成有限迁移的 contract 阶段。只有完整业务和六种 runtime 都就绪后，才移除旧最终回复提案执行、下一轮拒绝反馈及预先生成成功行的路径；既有人工命令和看板继续使用共享业务模块。

## Interfaces and boundaries

- 完整落实[规格 D9](../../bridge-skills.md)及[共同迁移约定](README.md)。不保留永久新旧双协议，不把新客户端包装成旧标签生成器。
- 迁移模型调用方式，不改变已有任务/草稿/确认卡的业务含义。存储有演进时明确版本、兼容读取与恢复，不以清库或重建任务完成切换。
- 本票处理新旧边界、升级与清理，不重复 P02/P05 的业务实现；其他 prompt 迁移仍延期。

## Acceptance criteria

- [ ] 最终回复中的旧 automation 标签不再执行，即使同轮同时有合法工具请求也只发生一次工具所代表的操作。
- [ ] 老会话恢复后取得新短契约和真实客户端入口；不因旧历史仍包含提案格式而保留可执行后门。
- [ ] 旧版本的提醒、agent 任务、等待补全草稿和待确认卡均能加载并继续完成原流程，旧有效卡片不是仅能读取不能使用。
- [ ] 现有人工命令、看板操作、任务触发和结果交付回归通过；已有身份/授权配置不被迁移覆盖。
- [ ] 删除不再使用的提案解析执行、预告成功、拒绝队列及临时迁移接线；保留仍有业务用途的解析/校验，不为清理删除人工命令能力。
- [ ] 产品文档、skill、schema 与状态文案只介绍当前入口；旧协议测试改为“旧标签无副作用”和存储升级回归，没有永久兼容开关。

## Verification loop

1. 用固定旧版本数据建立升级失败回归，完成旧卡片确认及后续触发；用新旧混合回复验证不重复执行。
2. 完成接线切换和有限清理，逐项证明没有仍在调用的旧执行路径；保留有效业务回归。
3. 运行升级、自然语言操作、确认/看板与 runtime 集成回归及 `pnpm ci:local`，把同一交付版本交给 P09。

**Spec coverage:** A15；A10–A12 的升级和唯一入口回归。
