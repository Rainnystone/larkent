# Task 5 — P05 查询并变更既有自动化任务

**Status:** ready-for-agent · 待代码实施授权
**Delivers:** 用户能在同一轮查询任务并请求替换、暂停、恢复或删除，沿用既有确认语义；状态冲突和重复请求不会误操作。
**Blocked by:** [P02](P02-create-reminder.md)
**Worker class:** judgment

## What to build

补齐 automation 管理操作。提醒与已有 agent 任务共享同一管理契约；管理既有任务不依赖 P04 的新 agent 创建路径。以任务当前状态为依据，不能只根据旧会话中展示的编号执行变更。

## Interfaces and boundaries

- 遵循[共同契约](README.md)与[规格 D6–D7](../../bridge-skills.md)，复用 P01 查询及 P02 操作编号/持久回执。
- 替换、删除、暂停、恢复逐项沿用已有业务确认规则，不能统一加确认或统一跳过确认；聊天命令、看板和新工具共用业务处理。
- 替换使用结构化排期，校验与预览与创建一致；变更范围由 profile/群真实归属决定。

## Acceptance criteria

- [ ] 查询返回当前可用目标及其状态；合法替换、删除、暂停、恢复经真实客户端执行，工具结果、卡片/看板与存储一致。
- [ ] 需要确认的操作只有实际确认后生效；不需要确认的操作返回实际应用结果，不能凭预计结果预报成功。
- [ ] 目标已删除、状态变化、过期确认和跨群/profile 编号均得到具体结果，不静默作用于其他目标。
- [ ] 所有新增写操作沿用去重、内容冲突、结果查询、取消和重启恢复语义；响应丢失不重复变更或发卡。
- [ ] 提醒和既有 agent 任务均可管理，暂停/恢复/替换后的实际调度与返回状态一致。
- [ ] 覆盖对应人工命令与看板回归，删除重复业务分支；不借本票迁移无关卡片、评论或会议说明。

## Verification loop

1. 从消息、真实客户端及现有任务记录建立各操作的失败回归，覆盖确认前后状态。
2. 加入旧编号、并发状态变化、重复请求和投递/保存失败，观察实际存储和后续触发。
3. 运行相关任务变更、看板、确认与调度 integration 测试及 `pnpm ci:local`。

**Spec coverage:** A10、A11、A12；A09 的替换排期一致性。
