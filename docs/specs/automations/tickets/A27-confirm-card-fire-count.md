# A27 — 确认卡「接下来 N 次」按实际个数；一次性只写该次时刻 / 共 1 次；30 天内结束的写「共 N 次」

Status: ready-for-agent
Severity: **low**（外观；A11 r5 2026-10-18 实测：所有一次性确认卡都是「接下来 3 次：」下面只有一个时间）
Blocked by: A22（同样改 `src/automations/confirm-card.ts` 的正文；A22 结算后保留的正文也应是改好后的）
Track: 推到现有 code 分支 `feat/automations-v2`（PR #49），**#49 合入前完成**，不开新 PR
Spec: [../../automations.md](../../automations.md) Solution（确认卡逐字列出接下来至多 3 次触发）、§8（一次性写「共 1 次」；30 天内结束写「共 N 次」）

## 场景（A11 r5，真实触发，2026-10-18 UTC+8）

- 15:07:53 一次性确认卡 om_…edac：「**接下来 3 次：**」下面只有 `2026-10-18 15:52`。om_…f127、om_…d013 同样，所有一次性卡都是。
- S1 周期卡 om_…0f11：时间窗只有 25 分钟，卡上写「约每月 3 次」。
- 临时测试：`every 10m 15:40-16:05 until 16:05`，now = 15:52 → 「接下来 3 次：」下面只有 `16:00`，并写「约每月 1 次」。

## 触发

1. 任何一次性任务的确认卡。
2. 周期任务剩余触发少于 3 次（临近结束时创建）。
3. 周期任务 `endAt` 在 30 天以内（「约每月 N 次」不成立）。

## 根因（`5552726`）

- `src/automations/confirm-card.ts:99`：`nextFires(schedule, now, 3)` 实际返回 0–3 个；`:111` 标签写死 `**接下来 3 次：**`，不按实际个数，也不区分一次性。
- `:66-80` `frequencyLine`：对 `endAt` 在 30 天内的周期任务也写「约每月 N 次」。

## 要做

- **一次性**：不写「接下来 N 次」段，改为一行「触发时间：YYYY-MM-DD HH:MM（共 1 次）」（与 A17 一致，不写每月次数）。
- **周期**：标签写 `接下来 ${fires.length} 次：`，下面逐行列出同样个数的时刻（最多 3 个）。0 个（创建时窗口内已无触发）→ 不出确认卡，按校验失败处理，原因写「结束前已没有可触发的时刻」，走 A24 的同条回复 / `/auto new` 的拒绝路径。
- **频率行**：`endAt − now < 30 天` 时写「共 N 次」（N = `now` 到 `endAt` 之间的全部触发数，用 `nextFires` 数到 `endAt`；若有 A23 的 `startAt`，从 `max(now, startAt)` 数起）；否则保持「约每月 N 次」。
- 文案以 bridge 渲染为准，确认卡内容与落库逐字一致（Spec §3）。A22 结算后保留的正文就是这里渲染的正文。
