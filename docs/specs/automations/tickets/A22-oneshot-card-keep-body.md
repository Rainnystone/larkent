# A22 — 一次性确认卡结算后保留正文

Status: ready-for-agent
Severity: **medium**（用户决定 2026-10-18：A20 (d) 结算后整张卡换成一行状态文字，成员看不到点的是哪个任务、什么时间）
Blocked by: A21（同样改一次性卡片 / 看板的更新路径）
Track: 推到现有 code 分支 `feat/automations-v2`（PR #49），**#49 合入前完成**，不开新 PR
Spec: [../../automations.md](../../automations.md) §3（确认卡）、§7（点击后卡片原地更新）
Amends: [A20](A20-board-tap-refresh.md) (d)

## 现象

按 A20 (d) 的实现，一次性卡片（`/auto` 草稿确认卡、「一个月」/「结束」等提示卡）被点「是」/「否」或过期后，原卡片整张被换成一行没有任务名的状态文字。群里事后看不出这张卡确认的是哪个任务、什么时间、下次什么时候触发。

## 用户决定（2026-10-18）

一次性卡片结算后，**保留原卡片正文**（任务描述、时间规则、下次触发时间等，与结算前一致），**只把「是」/「否」按钮行**换成一行结果文字：

| 结算方式 | 结果行 |
|---|---|
| 确认 | 已确认 #N（`/auto` 短编号） |
| 取消 | 已取消 |
| 过期 | 已过期 |
| 「结束」类提示卡选定结束时间 | 已指定结束时间 |

结算后卡片上**没有可点的按钮**。

## 要做

- 修改 A20 (d) 的结算渲染：从原卡片内容出发，去掉按钮行，在原位置放结果行；其余元素保持不变。不要重新拼一张只有状态行的卡片。
  - 正文来源二选一，写进 PR 说明并用单测锁住：(1) 发卡时把渲染所需的输入（或渲染后的正文元素）随卡片登记一起存下，结算时复用；(2) 结算时用登记的 draft / 任务数据重新渲染同一正文。草稿已被消费或任务已删除时，(2) 也必须能拿到正文，否则选 (1)。
- 覆盖 A20 (d) 的**所有**结算路径：
  - 点「是」、点「否」；
  - 到 TTL 过期（scheduler 或去抖队列触发）；
  - 进程停机期间过期、启动时补一次更新（startup catch-up）；
  - 并发点击中**输掉的一方**：得到 toast「此确认已失效」，不再次改写卡片；赢的一方写出的卡片同样保留正文。
- 结果行**不写点击者姓名**（与 A20 (d) 一致）。
- 写路径不变（A20 (a)/(b)）：回调先返回 toast，回调返回之后再原地更新卡片；更新检查响应码，失败记 `code` / `msg`，不 bump sequence。
- 服务端的 nonce / TTL 兜底检查保留。

## 验收

- [ ] 先写失败测试，再实现。
- [ ] 每种结算方式（确认、取消、过期、已指定结束时间、启动补更新）各一个测试，断言更新后的卡片：
  - 正文元素与结算前一致（任务描述、时间规则、下次触发时间等）；
  - 不含任何按钮（也不含 `disabled` 的按钮）；
  - 含对应结果行（「已确认 #N」/「已取消」/「已过期」/「已指定结束时间」），且不含姓名。
- [ ] 并发：两次几乎同时的点击，只有一次写卡；写出的卡片满足上面三条；另一次只得到「此确认已失效」。
- [ ] 正文来源的选择有单测锁住（草稿已消费 / 任务已删除时仍保留正文）。
- [ ] `pnpm ci:local` 绿；push 和 PR 两次 CI 在 macOS/Ubuntu/Windows 全绿。
- [ ] 真实客户端实测（A11）：确认卡点「是」、另一张点「否」、再一张等到过期、一张「结束」提示卡选定结束时间；四张卡都保留原正文，按钮行换成对应结果行，没有可点的按钮。

## 不做

- 不改看板（A20 (a)–(c)、A21）。
- 不改按钮权限（A18）。
- 不在回调响应里返回整张卡片。

## A11 需重跑的场景

A20 (d) 的三张卡（点「否」、点「是」、等过期）外加一张「结束」提示卡：结算后正文仍在，只有结果行替换了按钮行。
